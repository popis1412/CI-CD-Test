# 📑 Project: QA 테스트 분석 및 자동 리포팅 파이프라인 (Python & Jenkins)

본 프로젝트는 Excel 기반 테스트 케이스 수행 결과를 Python으로 집계하고,  
Jenkins 파이프라인을 통해 분석 결과를 HTML 리포트로 생성 및 공유하는 QA 자동화 환경을 구성한 것입니다.  

또한, Steam 결제 Mock 시스템을 활용하여 실제 사용자 흐름 기반 테스트 데이터 생성까지 포함한 E2E QA 구조를 구현했습니다.

---

## 1. 🚀 포트폴리오 개요 (Why GitHub & Jenkins?)

단순 스크립트 실행이 아닌, 테스트 → 데이터 생성 → 분석 → 공유까지 이어지는 흐름을 구성하기 위해 GitHub와 Jenkins를 활용했습니다.

* **지속적 테스트 환경 구성:**  
  `QA_Test.xlsx` 또는 `result.xlsx` 변경 시 GitHub Push를 트리거로 Jenkins 파이프라인이 실행되도록 구성했습니다.

* **데이터 이력 관리:**  
  테스트 결과 파일을 GitHub에서 관리하여 변경 이력을 추적하고, 최신 QA 결과를 공유할 수 있도록 했습니다.

* **자동화된 리포트 생성:**  
  반복적인 테스트 결과 집계 작업을 Python 스크립트로 자동화하고, HTML 리포트로 가시화했습니다.

---

## 2. 🏗 파이프라인 구조 및 산출물

전체 파이프라인은 4단계로 구성되며, 각 단계는 QA 과정에서 필요한 결과를 생성합니다.

| 단계 | 수행 내용 | 산출물 | 목적 |
| :--- | :--- | :--- | :--- |
| **1. 환경 검사** | Python 및 라이브러리(openpyxl) 확인 | 빌드 로그 | 실행 환경 정상 여부 확인 |
| **2. QA 결과 분석** | Excel 테스트 결과 데이터 집계 | FAIL Count | 실패 항목 확인 |
| **3. 리포트 생성** | HTML 리포트 생성 | `qa_report.html` | 테스트 현황 시각화 |
| **4. 결과 전파** | Slack으로 결과 전송 | 메시지 / 파일 | 팀 내 결과 공유 |

## 4. 💳 결제 시나리오 기반 테스트 데이터 생성

QA 서버에 구성된 Steam Mock 결제 기능을 통해, 실제 사용자 행동 기반으로 테스트 데이터를 생성합니다.

### 동작 흐름

1. QA 서버 접속
2. 결제 페이지(Mock) 진입
3. 결제 수행
4. 결제 성공 시 이벤트 발생
5. `result.xlsx` 생성 (PASS 데이터 기록)
6. Jenkins 파이프라인 실행

### 산출물

- `result.xlsx`
  - 결제 성공 기반 PASS 데이터
  - 이후 분석 및 리포트 생성에 활용

### 목적

- 수동 테스트 데이터 입력 제거
- 실제 사용자 흐름 기반 테스트
- E2E QA 환경 구성
